# Audit Work Block

1. Leer completos `AGENTS.md`, `docs/development_protocol.md` y `.agents/rules/investment-analyst-core.md` en una sesión fresca e independiente por Work Block. Resolver fail-closed el único Work Block y su único PR abierto por expected branch/base; releer literalmente Issue, branch, base y SHA vivo. Ejecutar `scripts/check_workflow_guards.py --live --phase audit` antes y después de reconciliar el marker; `--json` es diagnóstico no autoritativo y no puede resolver el target ni un gate. Modelo/cliente es metadata, no autoridad.
2. AUDIT es read-only respecto de source, branch, head, estado del candidato y workspace permanente: no ejecuta formatter, fixer ni comandos mutantes como `gh pr ready`, merge, cleanup, cierre del Issue o cambios de label. La única mutación autorizada es la estrecha y machine-owned del propio comentario AUDIT para publicar o reconciliar evidencia exact-SHA; no puede alterar source, branch, head ni estado irreversible. Antes de PASS intenta refutar el candidato. Contabilizar todos los archivos del diff base...SHA, inspeccionar el diff completo y contexto crítico, justificar exclusiones no materiales y mapear explícitamente cada acceptance, invariante, negativo, contradicción, compatibilidad, scope, secretos, pruebas debilitadas y superficies protegidas. BUILD/CI/smoke o filenames nunca sustituyen esta revisión semántica.
3. Reutilizar el gate literal `Python 3.12 quality` verde y ejecutar a lo sumo una prueba focalizada read-only por riesgo concreto. Verificar SHA vivo, BUILD único PASS, smoke, requested changes, threads y probes de cada fallo material BUILD/FIX, o declarar que no existieron. Reconciliar todos los markers AUDIT según el algoritmo global antes de publicar/actualizar el único PASS/FAIL con rango, contabilidad, matriz de evidencia, hallazgos y riesgo.
4. BLOCKER, MAJOR, evidencia crítica ausente, diff material incompleto, identificador stale/sintetizado, contradicción sin resolver, test debilitado sin equivalencia o probe sin verificar impiden PASS. Cuando la evaluación llega legítimamente a un resultado terminal, AUDIT siempre publica o reconcilia primero su único marker machine-owned exact-SHA: un resultado FAIL registra `status=FAIL` y termina `CHANGES REQUIRED`; un resultado PASS registra `status=PASS`. Después de esa mutación estrecha relee GitHub y ejecuta nuevamente `scripts/check_workflow_guards.py --phase audit`; no puede devolver PASS sólo en narrativa. Con PASS y policy HUMAN, el handoff termina `AWAITING HUMAN APPROVAL` y ejecuta cero ready/merge/cleanup, cierre del Issue o cambios de label. Sólo con PASS y policy AUTO termina AUDIT e inicia FINALIZE con un guard `--live --phase finalize` completo pre-ready, `gh pr ready`, y otro guard live completo post-ready antes de confirmar head y hacer squash con `--match-head-commit`; nunca usa admin/bypass y reconcilia Issue/label idempotentemente. Un GUARD FAILURE previo a un resultado legítimo conserva el fail-closed del guard y no muta evidencia ajena.

Devolver únicamente `AUDIT PASS`/`CHANGES REQUIRED` o `COMPLETE`/`FINALIZATION BLOCKED`, SHA, hallazgos materiales, riesgo y siguiente acción.
